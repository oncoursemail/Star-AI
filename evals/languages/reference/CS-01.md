It is a classic **deadlock**. `.Result` blocks the UI thread until the task finishes. The `await` inside
`GetStringAsync`'s continuation wants to resume on the UI thread's synchronization context, but that thread is blocked
waiting for it, so neither can proceed.

Fix: go async all the way and `await` the call. Event handlers are the one place where `async void` is acceptable:

```csharp
private async void LoadButton_Click(object sender, EventArgs e)
{
    try
    {
        var data = await client.GetStringAsync(url);
        outputBox.Text = data;
    }
    catch (HttpRequestException ex)
    {
        outputBox.Text = "Request failed: " + ex.Message;
    }
}
```

In library code that does not touch UI, also use `ConfigureAwait(false)`; never block on async code with `.Result` or
`.Wait()`.
