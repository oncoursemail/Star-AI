The script dies at `(( count++ ))`. A post-increment returns the **old** value, which is 0 on the first pass, and an arithmetic command whose value evaluates to 0 has exit status 1. With `set -e` (errexit) a non-zero status from a simple command ends the script, silently.

Fix it with an assignment, which always succeeds: `count=$((count + 1))`.

```bash
#!/usr/bin/env bash
set -euo pipefail
count=0
for f in levels/*.json; do
  count=$((count + 1))
  echo "loaded $f"
done
echo "total $count"
```

`(( ++count ))` also works here because the new value is never 0, but the assignment form is the one that can never trip errexit. Keep `set -euo pipefail`. I traced this by reading; run it with `bash -x` to see the last command executed.
