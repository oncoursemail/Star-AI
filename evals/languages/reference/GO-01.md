Go maps are **not safe for concurrent writes**. The runtime detects the data race and stops the program with a fatal
error, which is deliberately not a panic, so `recover()` cannot catch it.

Guard the map with a `sync.Mutex` (or give one goroutine ownership of the map and send it updates on a channel;
`sync.Map` suits append-mostly caches):

```go
type Hits struct {
    mu sync.Mutex
    m  map[string]int
}

func (h *Hits) Inc(path string) {
    h.mu.Lock()
    defer h.mu.Unlock()
    h.m[path]++
}
```

Find these bugs earlier with the race detector: `go test -race ./...` and run a `-race` build in staging.
