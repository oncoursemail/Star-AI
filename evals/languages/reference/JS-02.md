Node 24 runs `.ts` files by **type stripping**: it erases type annotations and runs the rest as JavaScript. It does not type-check and it ignores `tsconfig.json`. Stripping can only remove syntax. TypeScript features that generate runtime JavaScript cannot be stripped, so they fail with `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`. Both of your lines are such features: `enum Team { Red, Blue }` compiles to an object, and the parameter property `constructor(private hp: number)` compiles to an assignment `this.hp = hp`.

Fix: replace the enum with an `as const` object plus a string literal union type, and declare the field explicitly.

```ts
export const Team = { Red: "red", Blue: "blue" } as const;
export type Team = (typeof Team)[keyof typeof Team];

class Player {
  private hp: number;
  constructor(hp: number) { this.hp = hp; }
}
```

To catch this early, set `"erasableSyntaxOnly": true` (TypeScript 5.8+) and `"verbatimModuleSyntax": true` in tsconfig, use `import type` for type-only imports, and run `tsc --noEmit` in CI, because Node does not type-check. The old `--experimental-transform-types` flag is gone in Node 26, so do not rely on it. Use a full compiler (`tsc`) or a bundler only if you really need enums.
