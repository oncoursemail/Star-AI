Signed integer overflow is **undefined behaviour** in C (C23 made two's complement mandatory, but overflow is still UB).
Because a correct program can never overflow, the optimiser is allowed to assume `a + b` never overflows, and then
`a + b < a` with `b > 0` can never be true, so it removes the check at `-O2`.

Check *before* the addition, without overflowing. In C23 use `ckd_add` from `<stdckdint.h>` (GCC/Clang also provide
`__builtin_add_overflow`), or compare against `INT_MAX - b`:

```c
#include <stdckdint.h>

int safe_add(int a, int b, int *out) {
    int r;
    if (ckd_add(&r, a, b)) return -1;   /* true means the result did not fit */
    *out = r;
    return 0;
}
```

Test with `-fsanitize=undefined` to catch other overflows.
