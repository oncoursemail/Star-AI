The loop breaks because of **word splitting**. `$(ls *.png)` produces one string, and because it is unquoted Bash splits it on whitespace (the characters in IFS) and then globs each piece, so `stone wall.png` becomes the two words `stone` and `wall.png`. The same happens again with the unquoted `$f` and `${f%.png}` inside the loop.

Fix: let the shell glob the files directly (do not parse `ls` output) and quote every expansion:

```bash
#!/usr/bin/env bash
shopt -s nullglob            # no matches -> loop runs zero times
for f in *.png; do
  convert "$f" "${f%.png}.webp"
done
```

Each glob result is one word even with spaces, and the quotes keep it one word. ShellCheck reports the original as SC2086 (double quote to prevent globbing and word splitting). I have not run this; test it with a file named `stone wall.png`.
