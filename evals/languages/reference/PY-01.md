The bug is Python's mutable default argument. The default value `inventory=[]` is evaluated only once, when the `def` statement runs (at function definition time), not on every call. Every call that omits `inventory` gets the *same* list object, so `append` keeps adding to one shared list and each new player sees the previous players' items.

Fix: use `None` as a sentinel and create a new list inside the function body.

```python
def add_item(item: str, inventory: list[str] | None = None) -> list[str]:
    if inventory is None:
        inventory = []
    inventory.append(item)
    return inventory
```

In a dataclass, write `items: list[str] = field(default_factory=list)` instead. To confirm the fix, call `add_item("sword")` twice and check that the second result is `["sword"]`, not `["sword", "sword"]`. Linters flag this pattern too (Ruff rule B006).
