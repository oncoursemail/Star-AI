A destroyed Unity object is a "fake null": the C# wrapper still exists, but the native object is gone. Unity
**overloads** `==` (and the implicit bool conversion) so `target == null` is true after destruction. The `?.` and `??`
operators, and `is null`, do not call that overload: they only check for a real C# null reference, so they bypass
Unity's check and you get `MissingReferenceException`.

Use an explicit comparison (or the bool conversion) for anything derived from `UnityEngine.Object`:

```csharp
if (target != null)
{
    target.TakeDamage(10);
}
```

`if (target)` works too. Keep `?.` for plain C# objects only.
