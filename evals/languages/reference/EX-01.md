A GenServer processes one message at a time from its mailbox. While `handle_call({:join, ...})` waits about 8 seconds for the HTTP request, the room is blocked, so every other `GenServer.call(room, :state)` waits in the queue and exits after the default 5 second (5000 ms) timeout.

Fix: do not do slow I/O inside the callback. Fetch the profile in the caller before the call, or start the fetch in a `Task` (under a `Task.Supervisor`) and handle the result in `handle_info`, replying later with `GenServer.reply/2`, or use `handle_continue`:

```elixir
def handle_call({:join, player}, from, state) do
  Task.Supervisor.async_nolink(Game.TaskSup, fn -> {from, player, Profiles.fetch(player.id)} end)
  {:noreply, state}
end

def handle_info({ref, {from, player, profile}}, state) when is_reference(ref) do
  Process.demonitor(ref, [:flush])
  GenServer.reply(from, :ok)
  {:noreply, put_in(state.players[player.id], %{player | profile: profile})}
end
```

Raising the timeout would only hide the problem: the room would still freeze for every player during each join.
