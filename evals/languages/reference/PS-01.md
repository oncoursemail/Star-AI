`Get-Item` reports a missing path as a **non-terminating** error: it writes the error record to the error stream and carries on. `try/catch` only catches terminating errors, so the catch block never runs.

Make the error terminating for that call with `-ErrorAction Stop` (or set `$ErrorActionPreference = 'Stop'` for the whole script):

```powershell
try {
    $cfg = Get-Item -LiteralPath .\config\game.json -ErrorAction Stop
    Write-Host "found $($cfg.FullName)"
}
catch [System.Management.Automation.ItemNotFoundException] {
    Write-Warning "config missing, using defaults"
}
```

Catching the specific exception type keeps unrelated failures visible. I have not run this; check it by renaming the file and running the script.
