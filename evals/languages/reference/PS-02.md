No. Do not set `Unrestricted` machine-wide. For a developer machine the usual fix is `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`: local scripts run, downloaded scripts must be signed. If the script came from the internet, review it and run `Unblock-File` on it, or run it once with `pwsh -ExecutionPolicy Bypass -File C:\tools\build.ps1`.

The execution policy is **not a security boundary**. Microsoft documents it as a safety feature that stops scripts from running by accident; any user can bypass it (for example with `-ExecutionPolicy Bypass` or by pasting the code). What actually keeps unwanted scripts off managed PCs is application control: App Control for Business (WDAC) or AppLocker, which also puts PowerShell into Constrained Language Mode, plus Defender/AMSI scanning, script block logging and code signing with a trusted certificate.

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
Unblock-File C:\tools\build.ps1
```
