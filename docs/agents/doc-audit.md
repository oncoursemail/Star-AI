## Disposition and measurement limits

Of the 15 checked claims: **3 true**, **6 partly true**, **6 false**. The **12 partly true/false claims were corrected** in their source documentation. Three supported statements were left intact. Historical PR counts and released-source test counts must not be presented as interchangeable; publication does not verify all GPU, Studio, browser deployment or upgrade paths.

GitHub v0.9.0 publication was checked from the release tag and asset metadata on October 12, 2026 (published October 11, 2026). The release's test and physical acceptance counts were **read from its release notes**, not rerun here. The 26 pack folders were counted from GitHub's October 12, 2026 `star/next` source listing; this is not a count of validated, loadable or installer-shipped packs. The October 11 historical Roblox baseline was reported by `docs/evals.md` as `python -m star.evals run` on the fixed task sets followed by `python -m star.evals rescore`; the October 12 newer outcome is recorded in `docs/WEBSITE_RELEASE_CHECKLIST.md:9`. No local pytest, Vitest, real Windows installer, Roblox engine or external-site deployment check was performed for this audit. GitHub Actions checks for the draft PR are reported separately on the PR.

## Audit approach (alternatives considered)

- **Direct source-to-claim review (selected):** GitHub API read of exact source and release metadata, with a dated evidence table. No new dependency, licence or runtime cost; review must be repeated when code/releases change.
- **Existing Vitest documentation assertions:** uses already-present, MIT-licensed Vitest with no extra dependency or licence cost, but requires maintained literal fixtures and checks text fragments, not whether behavior is backed by implementation; upkeep means maintaining literal fixtures.
- **New third-party link checker (not selected):** would require a separate licence review and ongoing dependency/CI upkeep; network access and a new dependency add cost, while link status alone cannot establish product behaviour. No package selected or installed.

**No application code or tests were changed.** Documentation-only corrections are submitted for existing GitHub CI checks, which are not a real-device acceptance run.
