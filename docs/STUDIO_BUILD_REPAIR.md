# Studio build repair

This change repairs the build loop and private-place test pipeline. The local MCP and connector transport have separate source owners. It does not grant permission to publish a live game, alter the deny-list, or treat connector availability as a successful build.

## Target binding and script updates

The initial editable verdict is tied to a Studio instance, universe/place IDs, creator identity, and the native `game:GetDebugId(32):workspace:GetDebugId(32)` session identity. Two unsaved places may both have IDs `0/0`; that does not make them the same target. Every script update, edit Luau request, history undo, and play launch carries the original native identity and checks it inside the same engine call. A later host-side read alone cannot authorize a mutation after a place switch.

Script updates use `ScriptEditorService:GetEditorSource` and `UpdateSourceAsync`. The callback rechecks the native session, original script object, parent/path resolution, and complete source preimage before returning new text. The result must confirm the unique recording tag, script identity, and postimage. Missing/error/malformed responses remain unconfirmed. The [official ScriptEditorService reference](https://create.roblox.com/docs/reference/engine/classes/ScriptEditorService) is the API contract; offline stand-ins do not execute that API.

## History undo and uncertain operations

Each edit gets a unique `StarEdit_*` request tag. When STAR can own a recording, creation undo requires original object identity, unchanged postimage, and that unique recording at the top native undo entry. It checks the target and verifies deletion after Undo. Luau undo verifies the corresponding top redo entry. Roblox's [engine explanation](https://devforum.roblox.com/t/changes-to-luasourcecontainersource-are-not-captured-by-changehistoryservice/4590702) states that DataModel history ignores script `Source` changes, including `UpdateSourceAsync`. Existing source is therefore restored by an explicit reverse `UpdateSourceAsync` CAS against original object/session and full unchanged postimage, followed by an exact source readback. It does not claim to restore source through native history. The stand-in now models this distinction.

Native inspection established that the built-in Assistant owns an outer recording while `execute_luau` runs. STAR accepts that active recording rather than attempting a nested one, and never finishes or cancels someone else's recording. Confirmed receipts distinguish STAR-owned recording from connector-owned recording. Connector-owned script creation and Luau edits require **manual** native-history review; automatic Undo is refused because STAR cannot prove the connector's unique history boundary. Existing source can still be restored through its independent guarded reverse CAS, preserving unrelated owner objects. A STAR-owned source reversion also conservatively checks its saved native history boundary.

The [official ChangeHistoryService documentation](https://create.roblox.com/docs/reference/engine/classes/ChangeHistoryService) and its [detailed source reference](https://raw.githubusercontent.com/Roblox/creator-docs/main/content/en-us/reference/engine/classes/ChangeHistoryService.yaml) describe recording, undo availability, and history operations. A newer owner history entry blocks STAR-owned native Undo. Changed source, replacement object, failed Undo, or missing receipt stops recovery; the remaining journal is retained. Unknown connector history is never treated as a STAR-owned waypoint.

The journal is inserted **before** awaiting a mutating connector call. Cancellation or transport loss can occur after a write happened. Such an entry stays unknown, with no automatic retry or rollback claim. Undo is also marked unknown before dispatch, so a lost undo response cannot authorize repeated Undo. The desktop additionally supplies a durable SQLite uncertainty store. Before script/Luau/play-start/undo dispatch, and a stop following a confirmed start, it commits a pending token bound to the frozen native session, universe/place, creator, and validated host route. A transient connector Studio ID is not part of that binding. Only an exact known successful receipt or confirmed Playing state releases the matching token. Stop additionally requires the original Edit native session afterward. Confirmation persistence failure remains visibly unresolved.

That pending barrier survives a new guard, chat, or connection. Reconnect is not recovery. Host inspection and explicit acknowledgement are required before writes resume after uncertainty; there is no model acknowledgement tool. Invalid binding or corrupt/unavailable ledger refuses writes. Reads and explicit stop cleanup remain available, and a confirmed stop does not erase an uncertain launch or edit. Optional callers that pass no store retain offline/native stand-in compatibility; desktop connections always provide the home-scoped store. The in-memory detailed journal remains session-local, while durable rows contain only hashed binding, opaque token, operation kind and timestamp, without source, arguments or launcher details.

## Bounded play and cleanup

Play starts through `StudioTestService:ExecutePlayModeAsync` with the native target guard immediately before the call. A spawned closure avoids blocking the connector on the yielding test API. `starSession` and `starRequest` are arbitrary test arguments, not documented engine options or a built-in timeout. There is no fallback to an unbound `start_stop_play(true)` call. The [official StudioTestService reference](https://create.roblox.com/docs/reference/engine/classes/StudioTestService) marks the API as yielding and requiring Plugin Security.

An echoed request nonce only proves a launch request. STAR additionally needs Playing state and a fixed Server ownership probe confirming the original native session and request within 15 seconds, before releasing the launch's pending token. A foreign Playing session cannot confirm launch. It supports the existing tested JSON `playState` stand-in shape and one exact anchored connector text field, `- Current Studio Mode: Edit`, `Play`, or `Playing`. Unknown values, ambiguous duplicate mode fields, and error responses refuse confirmation. The parent captured real `Edit` and `Play` fields on its disposable blank; this evidence does not establish every future connector response format.

Cleanup freezes the original Edit identity and opaque request nonce before launch dispatch. It uses fixed host-owned Server code to verify `RunService:IsServer()`, universe/place and creator identity, and exact `StudioTestService:GetTestArgs()` values for that request. It repeats those checks inside the **same call** that invokes `EndTest({starStopped=request, starSession=session})`. A matching receipt plus the original Edit native debug-ID pair must be confirmed within 10 seconds. An already-Edit session needs the same original identity check and causes no stop mutation. Foreign tests, different unsaved blanks, missing remembered request, unknown state, and unverifiable Server arguments refuse cleanup. There is no raw `start_stop_play(false)` fallback. The [detailed StudioTestService contract](https://raw.githubusercontent.com/Roblox/creator-docs/main/content/en-us/reference/engine/classes/StudioTestService.yaml) documents Server-only EndTest, arbitrary retrievable test arguments, and asynchronous completion.

The Server bridge may lag behind the Playing state. Only a fixed read-only ownership probe's exact `Target is not reachable` or captured `Target is not reachable (createExecuteLuauBridge_loadCodeAsync, Server)` response is polled; the mutating EndTest call is never replayed after dispatch, response loss, cancellation, or an error. A confirmed start gets its own durable `play_stop` token; cleanup of this same guard's uncertain start retains its original `play_start` barrier and never clears it using a stop receipt. A corrupt ledger cannot grant further write permission, while exact owned cleanup remains possible. A new guard cannot automatically end an old uncertain play request whose nonce it does not know.

Cancellation, unread console output, or an uncertain start attempt triggers the same cached bounded cleanup in a `finally` path. AnyIO shielding protects cleanup from level-triggered cancellation used by the local MCP handler. Failed stop remains visible and unconfirmed. Native Luau may continue after client cancellation; this mechanism cannot guarantee termination of arbitrary native work. The [official Studio MCP documentation](https://create.roblox.com/docs/studio/mcp) describes connector tooling but does not specify every response format.

Guarded keyboard, mouse, and character-navigation inputs are temporarily unavailable, including during a confirmed STAR-owned test. The native tools accept a Studio ID without an atomic session/request token. A separate ownership read cannot bind a later raw input to that same test after a window switch. The guard refuses all three without dispatch; the own local MCP catalogue excludes them. Scene and console reads remain available. Restoring automated input needs a documented atomic target contract or a tested same-call native equivalent.

Required state/tree/script/screenshot reads must succeed before the build loop edits. Console read errors cannot become an empty error list. A playtest step succeeds only when actual play was confirmed, console was read, and stop was confirmed. Overall success additionally requires all required steps and a clean observed console. That is a bounded smoke result, not proof of gameplay quality or comprehensive test coverage.

## Private publish/test pipeline

`run_pipeline` pins the read-approved private `(universe_id, place_id)` through both `publish_place(..., only=target)` and `run_luau(..., only=target)`. Returned target IDs must match exactly; a positive Saved publication version must be returned and the test response must identify that version. Unexpected target/version, incomplete task, or task error stops the pipeline visibly.

The standard harness reports passed/failed/executed counts and named cases. Missing test containers, zero discovered modules/functions, invalid function entries, malformed reports, duplicate cases, inconsistent totals, and zero passed cases cannot be success. Case counts are bounded at 200. Reports containing actual failures remain failures. An executed function count is not proof that the function contains useful assertions; authors remain responsible for meaningful tests.

## Evidence and remaining acceptance

The new repair fixtures use disposable profiles and stand-in objects only. They cover after-read target drift, same-ID different native sessions, source/object callback conflicts, owner history and postimage conflicts, failed/no-effect/lost/cancelled Undo, pending journals before dispatch, cancellation during request and running play, AnyIO cancel scopes, failed reads/console/stop, unknown state, and bounded request-without-play failures. Real temporary SQLite fixtures also verify cross-connection barriers, changed transient Studio IDs, exact dispatch tokens, confirmation failure, corrupt ledgers and missing binding, with no source/arguments saved. The pipeline fixtures cover private target/version pinning and strict report validity. Legacy loop tests retain complete build/fix/history-undo behavior.

These tests validate Python decisions and an explicit simulation contract. They do not validate execution of generated Luau, Plugin Security compatibility, actual history waypoint names, real play mode timing, or production gameplay. Safe native acceptance must use an explicitly approved disposable blank, capture start/stop and undo results, preserve uncertainty on failure, and verify no other Studio session was touched. The parent agent owns that acceptance and final combined application checks.

The parent's first native script-create smoke failed and the follow-up read confirmed that named script was absent. The unknown journal remained retained and no replay was attempted. A subsequent read-only diagnostic confirmed that the generated bound script compiled, the exact blank session stayed stable, and `IsRecordingInProgress()` was true inside the Assistant tool; its console reported refusal to begin the nested recording. That cause and the source-history mismatch have now been corrected in code and fixtures. Bounded redacted diagnostics preserve future native failure details.

Subsequent parent-owned native probes on the disposable blank confirmed connector-owned creation/edit, anchored instance construction, two Server runtime assertions, native Play mode, exact `GetTestArgs` binding, atomic target-bound EndTest followed by Edit, and reverse-source-CAS restoration. The final integrated own-local-MCP start followed immediately by bound stop restored the original Edit session and left no durable pending operation. Those captures are observations from that one session. Screenshot/UI rendering was not accepted and remains separate. Passing offline tests and this disposable-blank smoke do not establish S2 compatibility or gameplay quality.
