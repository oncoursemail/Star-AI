# Flax Engine: STAR engine research
**Verified 2026-10-13 against official docs. Current stable: 1.12 (build 1.12.6912, May 18-19, 2026); 1.13 is in development.** Free to use; 4% royalty on gross revenue above $250,000 per calendar quarter once you ship. Source available on GitHub.

## At a glance
| | |
|---|---|
| Best for | C# (or C++) developers who want a Unity-like workflow with a modern renderer (DDGI, Global SDF) and full engine source; mid-size 3D PC/console games |
| Weak at | Small community and asset ecosystem; web export is experimental and has no C#; documentation thinner than Unity/Godot |
| Language(s) | C# 14 on .NET (editor needs .NET SDK 10), C++ (native scripting with codegen bindings), Visual Scripting (Visject graphs) |
| Editor / tooling | Flax Editor (Windows, Linux, macOS), Flax.Build build tool, VS / VS Code / Rider / CLion integrations, Game Cooker |
| Platforms (export) | Windows, Linux, macOS, Android, iOS, Xbox One, Xbox Series, PlayStation 4/5, Switch (consoles need platform access), Web (WebGPU, experimental since 1.12) |
| License / cost | Free; 4% royalty above $250k gross per quarter; custom licensing available |
| Roblox-likeness | low: Unity-style actor/script engine; built-in high-level networking exists but no hosting, avatars or cloud data |

## Architecture and lifecycle
- **Actors** form the scene tree (`Scene` → `Actor` children). Actor types are concrete scene objects: `StaticModel`, `AnimatedModel`, `Camera`, `DirectionalLight`/`PointLight`/`SpotLight`/`SkyLight`, `BoxCollider`/`SphereCollider`/`CapsuleCollider`/`MeshCollider`, `RigidBody`, `CharacterController`, `UICanvas`, `UIControl`, `EmptyActor`, `AudioSource`, `ParticleEffect`, `NavMeshBoundsVolume`, and others.
- **Scripts** (`FlaxEngine.Script`) attach to actors, any number per actor. A script's lifetime follows its actor. You can also write custom **Actor** types for new scene objects.
- **Script event functions** (override in C#; no base call needed):
  - `OnAwake()`: after load, before enable/start, once.
  - `OnStart()`: once, before the first update; always before the first `OnEnable`.
  - `OnEnable()` / `OnDisable()`: register and unregister events here.
  - `OnUpdate()`, `OnLateUpdate()`, `OnFixedUpdate()`, `OnLateFixedUpdate()`.
  - `OnDestroy()`: once.
  - `OnDebugDraw()` / `OnDebugDrawSelected()`: the only events called at edit time.
  - C++ scripts must set `_tickUpdate = true` (and `_tickLateUpdate`, `_tickFixedUpdate`, `_tickLateFixedUpdate`) in the constructor to get the tick events.
- Update, fixed update and draw can run at different rates. The order of gameplay events between scripts is not stable; init/deinit order is.
- **Plugins**: `GamePlugin` / `EditorPlugin` for global systems. **Prefabs** (`.prefab`) are spawned with `PrefabManager.SpawnPrefab(prefab, parent)`.
- **Serialization**: JSON. Public fields/properties, or members marked `[Serialize]`, are saved unless they have `[NoSerialize]` (not static, readonly or const). Deserialization *populates* existing objects. References to actors/scripts serialize as GUIDs.
- Units are **centimeters** (1 unit = 1 cm; default gravity is about -981 on Y). **Y-up**, left-handed.

## Project layout
```
MyGame/
  MyGame.flaxproj                 # project file (engine version, references)
  Content/                        # assets (.flax binary assets, .scene and .prefab JSON, .json settings)
    GameSettings.json, Scenes/, Materials/ ...
  Source/
    Game/                         # main C# / C++ game module
      Game.Build.cs               # module build rules (add Tags["Network"] here for networking codegen)
      MyScript.cs
    GameTarget.Build.cs, GameEditorTarget.Build.cs
  Cache/  Binaries/  Logs/        # generated, do not commit
  MyGame.slnx + .csproj           # generated by the editor
```
- Scripts must live under `Source/<Module>/`. Create them in the Content window (Source folder > New > C# Script).
- Settings assets: `GameSettings`, `InputSettings`, `PhysicsSettings`, `GraphicsSettings`, `NetworkSettings`, `LayersAndTagsSettings`.

## Scripting idioms
```csharp
using FlaxEngine;

public class Spinner : Script
{
    [Tooltip("Degrees per second"), Limit(0, 720)]
    public float Speed = 90.0f;                 // public field = serialized + shown in Properties

    [Serialize] private int _spins;             // private but saved
    [NoSerialize] public float Debug;           // public but not saved

    public override void OnUpdate()
    {
        Actor.LocalOrientation *= Quaternion.RotationY(Mathf.DegreesToRadians * Speed * Time.DeltaTime);
    }
}
```
- Access: `Actor` (owner), `Actor.Position` / `Actor.Orientation` / `Actor.Scale` (world), `Actor.LocalPosition`, `Actor.Transform`, `Actor.Parent`, `Actor.GetChild<T>()`, `Actor.FindActor<T>()`, `Actor.GetScript<T>()`, `Actor.AddScript<T>()`, `Actor.As<T>()` (cast the owning actor), `Level.FindActor(...)`, `Level.FindScript<T>()`.
- Create and destroy: `var light = new PointLight { Parent = Actor };`, `Actor.AddScript<Player>()`, `Destroy(obj)` or `Destroy(obj, seconds)`. Do not use constructors for scene objects except to set defaults.
- References to other objects: public `Actor`/typed fields (`public Light LightToControl;`), `JsonAssetReference<T>`, `Prefab`, `SceneReference`.
- Events: C# events on engine objects (`collider.TriggerEnter += Handler;`). Subscribe in `OnEnable`, unsubscribe in `OnDisable`.
- Logging: `Debug.Log`, `Debug.LogWarning`, `Debug.LogError`. Debug shapes: `DebugDraw.DrawSphere(...)`.
- Scene changes: `Level.ChangeSceneAsync(sceneReference)` / `Level.LoadSceneAsync(...)`.
- C++ script skeleton: `API_CLASS() class GAME_API MyScript : public Script { API_AUTO_SERIALIZATION(); DECLARE_SCRIPTING_TYPE(MyScript); ... }`, with `API_FIELD()` / `API_FUNCTION()` tags generating C# bindings.

## Pitfalls (what AI answers get wrong)
1. **Unity-isms**: `MonoBehaviour`, `void Update()` (no override), `transform.position`, `GetComponent<T>()`, `Time.deltaTime`, `Input.GetKey(KeyCode.W)`, `OnTriggerEnter(Collider other)` magic methods. Flax: `Script`, `public override void OnUpdate()`, `Actor.Position`, `Actor.GetScript<T>()` / typed actor fields, `Time.DeltaTime`, `Input.GetKey(KeyboardKeys.W)`, and subscribing to `Collider.TriggerEnter`/`TriggerExit` events (handler receives `PhysicsColliderActor`).
2. **Colliders are actors**, not components on a GameObject. A trigger is a collider actor with `IsTrigger = true`; get it with `Actor.As<Collider>()` when the script sits on the collider.
3. **Units**: centimeters. A "speed of 5" moves 5 cm/s; character speeds are in hundreds.
4. **Vector types**: `Vector3` uses `Real` (double when large-world support is enabled). Use `Float3` when you need `float`-only math (GPU data, buffers).
5. **1.12 color pipeline**: new `Gamma Color Space` option (on by default keeps old behavior). New projects should turn it off and use linear workflow; migrating projects must reimport sRGB textures and retune post FX.
6. **1.12 API changes**: `CreateWindowSettings::IsRegularWindow` deprecated (use `WindowType`); `GPUContext::ClearState` renamed `ResetState`; `GPUTimerQuery` deprecated; lights with `InverseSquaredFalloff` no longer need huge `Brightness`; Visject surface API changed a lot.
7. **1.11 changes**: depth buffer is 24-bit depth + 8-bit stencil (Object Layer in the stencil bits); `ISceneRenderingListener` events are no longer mutex-guarded (lock your data); material instance creation no longer overrides base parameters by default; minimum Windows 10 with SSE4.2, macOS 13, iOS 15.
8. **1.10 changes**: variable vertex formats (`MeshAccessor` API replaces fixed vertex structs); C++ `Vector3::Angle` returns degrees; 9-slice brushes changed; `GPUVertexLayout` instead of `META_VS_IN_ELEMENT`.
9. **.NET version**: 1.8 moved to .NET 8 SDK as base; current docs say the editor requires **.NET SDK 10** and C# 14. Do not tell users to install .NET 6/7.
10. **Networking needs codegen**: `[NetworkRpc]` and `[NetworkReplicated]` only work if the module build script adds `Tags["Network"] = string.Empty;` (and `options.PublicDependencies.Add("Networking")`), and if the object is registered with `NetworkReplicator.AddObject(this)`.
11. **Web export (1.12) has no C#**. Only C++/Visual Scripting games run in the browser for now.
12. 1.13 (in development) renames `GPU_ENABLE_DIAGNOSTICS` to `GPU_ENABLE_DEBUG_LAYER` and disables the automatic GPU debug layer in Debug builds (`-gpudebug`).
13. Linux uses the **SDL** backend by default since 1.12. Drag&drop on X11 with XInput2 is broken; use `-wayland`.

## Rendering
- Deferred PBR renderer with forward pass for transparency. **DDGI** (dynamic diffuse GI, ray traced on the Global SDF; production-ready in 1.12 with a fallback probe mode), **Global SDF** and **Global Surface Atlas**, volumetric fog, SSR (optimized in 1.12), SSAO, TAA, motion blur, depth of field, eye adaptation, tone mapping, color grading, environment probes (box projection in 1.12).
- Materials are node graphs (Visject Material Editor); material instances; custom lit shading model (1.11) for toon/cel shading; mask decals via stencil (1.11).
- Backends: DirectX 11, DirectX 12, Vulkan, WebGPU (Web), platform-native on consoles.
- 1.12: MSDF fonts, `ProfilerGPU.Dump` and `GPUDevice.DumpResources` debug commands.

## Physics
- PhysX-based. Actors: `RigidBody` (parent of colliders), `BoxCollider`, `SphereCollider`, `CapsuleCollider`, `MeshCollider` (triangle meshes cannot be triggers), `CharacterController`, joints (`FixedJoint`, `HingeJoint`, `SliderJoint`, `SphericalJoint`, `DistanceJoint`, `D6Joint`), `WheeledVehicle`, cloth, ragdolls. Spring Bone physics node for animation (1.12).
- `CharacterController` (capsule): `Move(Vector3 displacement)` and `SimpleMove(Vector3 speed)` return `CollisionFlags`; properties `IsGrounded`, `Velocity`, `SlopeLimit`, `StepOffset`, `Radius`, `Height`, `Resize(height, radius)`, `AutoGravity`.
- Collision events: `Collider.CollisionEnter` / `CollisionExit` (with `Collision` data); trigger events `TriggerEnter` / `TriggerExit`.
- Raycasts: `Physics.RayCast(origin, direction, out RayCastHit hit, maxDistance, layerMask)` and shape casts (`BoxCast`, `SphereCast`, ...) per the raycasting docs.
- Fixed step settings in Physics Settings. Do physics forces in `OnFixedUpdate`.

## Input
- Raw: `Input.GetKey(KeyboardKeys.W)`, `Input.GetKeyDown(...)`, `Input.GetKeyUp(...)`, `Input.InputText`, mouse `Input.GetMouseButton(MouseButton.Left)`, `Input.MousePosition`, `Input.MousePositionDelta`, gamepads.
- **Virtual input** (Input Settings asset): actions and axes. `Input.GetAction("Fire")`, `Input.GetAxis("Horizontal")`, or typed helpers `new InputEvent("Fire")` (`.Pressed += ...`, `Dispose()` in `OnDestroy`) and `new InputAxis("MouseX")` (`.Value`).
- Cursor: `Screen.CursorLock = CursorLockMode.Locked; Screen.CursorVisible = false;`.

## UI
- `UICanvas` actor (screen space, camera space or world space) with `UIControl` child actors. Each `UIControl` wraps a `Control` (`Label`, `Button`, `Image`, `TextBox`, `Slider`, `CheckBox`, `ProgressBar`, `VerticalPanel`, `GridPanel`, `Border`, `RichTextBox`, ...).
```csharp
public UIControl ScoreLabel;                       // assign in editor
ScoreLabel.Get<Label>().Text = "Score: 3";
var button = new Button { Text = "Play" };
button.Clicked += () => Debug.Log("Play");
MyButtonControl.Control = button;
```
- Anchors and pivots on controls; `CanvasScaler` for resolution scaling; brushes for 9-slice images; localization via `LocalizedString`.

## Networking and multiplayer
- Built-in high-level networking (`FlaxEngine.Networking`): `NetworkManager.StartServer()` / `StartClient()` / `StartHost()` / `Stop()`; events `ClientConnecting` (validate/reject), `ClientConnected`, `ClientDisconnected`; `NetworkManager.ServerClientId = 0`. Transport is pluggable (`INetworkDriver`, ENet by default).
- `NetworkReplicator`: `AddObject(this)` in `OnEnable`, `RemoveObject(this)` in `OnDisable`; `SpawnObject(actor)` after `PrefabManager.SpawnPrefab`; roles and ownership (`GetObjectRole`, `SetObjectOwnership`, `IsObjectOwned`); `DirtyObject(obj)`; optional `NetworkReplicationHierarchy` for interest management and per-object replication rate (`ReplicationFPS`).
- State: `[NetworkReplicated]` on fields/properties (C++: `API_FIELD(NetworkReplicated)`).
- RPCs: `[NetworkRpc(Server = true)]` (client → server), `[NetworkRpc(Client = true)]` (server → clients), with `Channel = NetworkChannelType.Unreliable/Reliable/...`; optional `NetworkRpcParams` argument for `SenderId` / `TargetIds`.
- There is also a low-level `NetworkPeer` API and an "online" platform layer (Steam etc.) for sessions.

## Save data
- No save-game system. Use `JsonSerializer.Serialize(obj)` / `JsonSerializer.Deserialize<T>(json)` (FlaxEngine.Json) and write files under `Globals.ProductLocalFolder` (per-user app data folder) with `System.IO.File`.
- `[Serialize]`/`[NoSerialize]` rules apply to your save objects as well.

## Performance
- Use the built-in Profiler window (CPU, GPU, memory; new memory profiler in 1.11) and `ProfilerGPU.Dump` (1.12).
- Mark static actors with `StaticFlags` for baked lighting, navigation and replication-hierarchy optimizations.
- Avoid per-frame allocations in `OnUpdate`. Cache `GetScript<T>()` results in `OnStart`.
- Use LODs, the Global SDF budget settings, texture streaming; `Arena Allocator` for C++ (1.11).
- Long work: `JobSystem`, `Task`s, or `ThreadPool`. Touch scene objects only from the main thread unless documented safe.

## Build and export
- **Game Cooker** window (Tools > Game Cooker): pick platform and configuration (Debug/Development/Release), set output, Build. Presets can be saved and run from the command line (`FlaxEditor -build <preset>`; check the Game Cooker docs for exact flags).
- Code is built by Flax.Build; the editor hot-reloads C# scripts on save.
- Platform SDKs: Android SDK/NDK 27+, Xcode 16.4+ for Apple (1.12), console SDKs under NDA.

## Common bugs and fixes
| Symptom | Cause | Fix |
|---|---|---|
| Script never updates | Unity-style `void Update()` | `public override void OnUpdate()` |
| C++ script `OnUpdate` not called | Tick flags not set | `_tickUpdate = true;` in constructor |
| Trigger handler never runs | Not subscribed, or `IsTrigger` off, or mesh collider | `collider.TriggerEnter += Handler` in `OnEnable`; enable `IsTrigger`; use a primitive collider |
| Player barely moves | Units are cm | Multiply speeds (for example 600 cm/s) |
| Character floats / no gravity | Using `Move` without gravity | Add gravity to the displacement or use `SimpleMove` / `AutoGravity` |
| RPC does nothing | Module missing `Network` tag or object not registered | Add `Tags["Network"]` in `Game.Build.cs`; `NetworkReplicator.AddObject(this)` |
| Colors look washed out after 1.12 upgrade or after toggling Gamma | sRGB/linear workflow change | Follow the 1.12 migration (reimport sRGB textures, adjust post FX) |
| Depth precision artifacts after 1.11 | 24-bit depth + stencil | Adjust camera near/far planes |
| Web build fails with C# | C# unsupported on Web (1.12) | Use C++/Visual Scripting for web targets |
| Editor will not open project | .NET SDK 10 missing | Install .NET SDK 10 |

## Minimal example
Player with a `CharacterController` moved by WASD; coins are trigger colliders that add score.
```csharp
using FlaxEngine;
using FlaxEngine.GUI;

public class PlayerMove : Script
{
    public float Speed = 600.0f;          // cm per second
    public float Gravity = -981.0f;
    public UIControl ScoreLabel;          // UIControl with a Label
    public int Score;

    private CharacterController _controller;
    private float _verticalVelocity;

    public override void OnStart()
    {
        _controller = Actor.As<CharacterController>();
    }

    public override void OnUpdate()
    {
        var input = new Vector3(
            (Input.GetKey(KeyboardKeys.D) ? 1 : 0) - (Input.GetKey(KeyboardKeys.A) ? 1 : 0),
            0,
            (Input.GetKey(KeyboardKeys.W) ? 1 : 0) - (Input.GetKey(KeyboardKeys.S) ? 1 : 0));
        if (input.LengthSquared > 1) input.Normalize();

        _verticalVelocity = _controller.IsGrounded ? 0 : _verticalVelocity + Gravity * Time.DeltaTime;
        var move = input * Speed + new Vector3(0, _verticalVelocity, 0);
        _controller.Move(move * Time.DeltaTime);
    }

    public void AddScore()
    {
        Score++;
        if (ScoreLabel) ScoreLabel.Get<Label>().Text = "Score: " + Score;
    }
}

public class Coin : Script
{
    public override void OnEnable()  { Actor.As<Collider>().TriggerEnter += OnTriggerEnter; }
    public override void OnDisable() { Actor.As<Collider>().TriggerEnter -= OnTriggerEnter; }

    private void OnTriggerEnter(PhysicsColliderActor other)
    {
        var player = other.GetScript<PlayerMove>();
        if (player == null) return;
        player.AddScore();
        Destroy(Actor);
    }
}
```
Setup: put `PlayerMove` on the `CharacterController` actor; put `Coin` on a `SphereCollider` with **Is Trigger** checked.
