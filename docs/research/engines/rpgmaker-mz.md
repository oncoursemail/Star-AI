# RPG Maker MZ: STAR engine research
**Verified 2026-10-13 against official docs. Current stable: 1.10.0 (announced 2 Feb 2026 on the official Japanese forum; Yanfly changelog dates it 30 Jan 2026). Previous: 1.9.0 / 1.9.1 (2025).** Proprietary, one-time paid editor (Gotcha Gotcha Games / Kadokawa); games you make are yours to sell royalty-free under the EULA. Sister product RPG Maker Unite (Unity add-on, C#) is at 1.3.1 (2 Sep 2026).

## At a glance
| | |
|---|---|
| Best for | Classic JRPG-style 2D games (tile maps, turn-based battles, menus, events) built mostly with the database and event editor, extended by JavaScript plugins |
| Weak at | Anything not RPG-shaped (action/physics/platformer need heavy plugins), 3D, multiplayer, large-team source control (JSON data files merge badly) |
| Language(s) | Event commands (visual); JavaScript (ES2015+) plugins that patch the core scripts `rmmz_*.js` |
| Editor / tooling | Native editor (Windows/macOS, Steam) with Database, Map editor, Event editor, Plugin Manager; playtest runs in NW.js; any text editor for plugins (VS Code + community type definitions) |
| Platforms (export) | Deployment: Windows, macOS, Web browsers (official help). Android/iOS by wrapping the web build with third-party tools (Cordova/Capacitor), not an official one-click target |
| License / cost | Paid one-time licence (Steam/official store; price varies by sale). Core scripts and official plugins ship with the editor |
| Roblox-likeness | low: single-player, editor-driven data, prototype-patching plugins instead of a scripted instance tree |

## Architecture and lifecycle
- **Core scripts** in `js/`: `rmmz_core.js` (Graphics, Bitmap, Sprite, Window, Input, TouchInput, JsonEx, Utils, WebAudio, Tilemap on PixiJS 5), `rmmz_managers.js` (DataManager, ConfigManager, StorageManager, ImageManager, AudioManager, SceneManager, BattleManager, PluginManager...), `rmmz_objects.js` (Game_* model classes), `rmmz_scenes.js` (Scene_*), `rmmz_sprites.js` (Sprite_*, Spriteset_*), `rmmz_windows.js` (Window_*). `js/main.js` loads them, then `js/plugins.js` (generated by Plugin Manager) lists enabled plugins in order.
- **Three layers:**
  - `Game_*` = game state, saved (Game_System, Game_Party, Game_Actor, Game_Player, Game_Map, Game_Event, Game_Variables, Game_Switches, Game_Interpreter...). Global singletons `$gameSystem`, `$gameParty`, `$gamePlayer`, `$gameMap`, `$gameVariables`, `$gameSwitches`, `$gameTemp`, `$gameMessage`, `$gameTroop`.
  - `Scene_*` = screens with an update loop (Scene_Boot -> Scene_Splash (1.8.0+) -> Scene_Title -> Scene_Map / Scene_Battle / Scene_Menu...). `SceneManager.goto(Scene_X)`, `push`, `pop`.
  - `Window_*` / `Sprite_*` = presentation. Windows are created by scenes and added with `this.addWindow(win)`.
- **Database**: `data/*.json` loaded into `$dataActors`, `$dataItems`, `$dataSkills`, `$dataMap`, `$dataSystem`... (read-only templates; never store progress there).
- **Frame loop**: SceneManager updates the current scene each frame (60 fps logic); Scene_Map updates `$gameMap`, `$gamePlayer`, events and interpreters.
- **Events**: map/common events contain event command lists executed by `Game_Interpreter` (each command is `commandNNN`; e.g. Plugin Command MZ = `command357`, MV-style = `command356`, deprecated).
- **Plugins** are plain scripts run in load order at boot; they **alias and override prototype methods** of core classes. No module system, everything is global.

## Scripting idioms
**Plugin skeleton (official tutorial pattern):**
```js
/*:
 * @target MZ
 * @plugindesc Adds a "Give Gold" plugin command.
 * @author You
 * @url https://example.com
 * @help
 * Use the plugin command "Give Gold" from an event.
 *
 * @param bonusPercent
 * @text Bonus %
 * @type number
 * @min 0
 * @default 0
 *
 * @command giveGold
 * @text Give Gold
 * @desc Adds gold to the party.
 *
 * @arg amount
 * @text Amount
 * @type number
 * @min 1
 * @default 100
 */
(() => {
  "use strict";
  const pluginName = "GiveGold";                       // must equal the file name GiveGold.js
  const params = PluginManager.parameters(pluginName); // all values are STRINGS
  const bonus = Number(params.bonusPercent || 0);

  PluginManager.registerCommand(pluginName, "giveGold", args => {
    const amount = Number(args.amount);                 // args is an object of strings
    $gameParty.gainGold(Math.floor(amount * (1 + bonus / 100)));
  });
})();
```
- `PluginManager.registerCommand(pluginName, commandName, func)`: core stores `pluginName + ":" + commandName`; the interpreter calls `func.bind(interpreter)(args)`. Use `function (args) { this.character(0) }` (not an arrow function) when you need the `Game_Interpreter` as `this`.
- Plugin name for the command is taken from the **file name** (`Utils.extractFileName(params[0])`), so renaming the .js file breaks existing event commands.
- `PluginManager.parameters(name)` is case-insensitive and returns strings; `struct<...>` and arrays are JSON strings: `JSON.parse(params.list)`.

**Aliasing (the core idiom):**
```js
const _Game_Picture_show = Game_Picture.prototype.show;
Game_Picture.prototype.show = function() {
  _Game_Picture_show.apply(this, arguments);   // keep original behaviour and other plugins' aliases
  // added behaviour
};
```
Prefix the saved function with the class and method name; always call it with `.apply(this, arguments)` / `.call(this, ...)`. Overwriting without calling the original breaks every plugin loaded before yours.

**Header annotations (official MZ tutorial, section 4.3):**
- All plugins: `@target MZ` (required to mark MZ plugins), `@plugindesc`, `@author`, `@help`, `@url`.
- Parameters: `@param`, `@text`, `@desc`, `@default`, `@type`, `@parent`; type extras `@min`, `@max`, `@decimals`, `@dir`, `@on`, `@off`, `@option`, `@value`.
- `@type` values: `string`, `multiline_string`, `file`, `number`, `boolean`, `select`, `combo`, `actor`, `class`, `skill`, `item`, `weapon`, `armor`, `enemy`, `troop`, `state`, `animation`, `tileset`, `common_event`, `switch`, `variable`, `string[]` (any type + `[]`), `struct<Name>` with a separate `/*~struct~Name: ... */` block.
- Commands: `@command`, `@arg` (+ `@text`, `@desc`, `@type`, `@default` like params).
- Dependencies: `@base` (required plugin), `@orderAfter`, `@orderBefore`. Plugin Manager warns when order is wrong.
- Deployment asset protection: `@requiredAssets img/pictures/foo`, `@noteParam`, `@noteDir`, `@noteType file`, `@noteData items`. MV's `@require` is discontinued.
- Localised help: `/*:ja ... */` blocks per language, `/*: ... */` default.

**Windows in MZ take a Rectangle:**
```js
class Window_GoldHud extends Window_Base {
  initialize(rect) {
    super.initialize(rect);
    this.refresh();
  }
  refresh() {
    this.contents.clear();
    this.drawText(`${$gameParty.gold()} G`, 0, 0, this.innerWidth, "right");
  }
}
```
**Common state APIs:** `$gameVariables.value(id)` / `.setValue(id, v)`, `$gameSwitches.value(id)` / `.setValue(id, bool)`, `$gameSelfSwitches`, `$gameParty.gainGold(n)`, `$gameParty.gainItem($dataItems[id], n)`, `$gamePlayer.x/y`, `$gameMap.mapId()`, `$gameMessage.add(text)`, `SceneManager.push(Scene_Menu)`, `AudioManager.playSe({ name: "Coin", volume: 90, pitch: 100, pan: 0 })`, `ImageManager.loadPicture(name)`, `Input.isTriggered("ok")`, `Input.isPressed("left")`, `TouchInput.isTriggered()`.

**Notetags:** read `$dataItems[id].meta.MyTag` (DataManager extracts `<MyTag:value>` from the note box into `meta`).

## Pitfalls (what AI answers get wrong)
1. **MV plugin command style.** MV used `Game_Interpreter.prototype.pluginCommand = function(command, args)` with space-split string arrays. In MZ that hook is a deprecated no-op path (`command356`); use `@command`/`@arg` + `PluginManager.registerCommand`, where `args` is an **object** (`args.amount`), not `args[0]`.
2. **Missing `@target MZ`.** Without it the editor treats the file as an MV plugin.
3. **MV file names.** MV core is `rpg_core.js`, `rpg_managers.js`, `rpg_objects.js`, `rpg_scenes.js`, `rpg_sprites.js`, `rpg_windows.js`; MZ is `rmmz_*.js`. Don't tell users to edit `rpg_windows.js` in an MZ project, and never edit core files at all: write a plugin.
4. **Window constructor signature.** MZ: `new Window_Base(new Rectangle(x, y, w, h))`; MV: `new Window_Base(x, y, width, height)`. Scenes in MZ compute rects in helper methods (`helpWindowRect()`, etc.).
5. **Parameters are strings.** `PluginManager.parameters()` values and command args are strings; `"false"` is truthy. Convert with `Number()`, `=== "true"`, `JSON.parse()`.
6. **Plugin name mismatch.** `pluginName` in code must equal the file name (without .js). Mismatch = commands silently do nothing (callCommand only runs if a function is registered for `file:command`).
7. **Arrow function vs `this`.** In `registerCommand`, an arrow function loses the interpreter; use `function (args) {}` to call `this.character(0)` or `this.wait(n)`-style interpreter helpers.
8. **Custom classes in save data.** `JsonEx` stores the constructor name in `"@"` and restores with `window[name]`. A class declared inside the plugin IIFE is not on `window`, so after loading it becomes a plain object (methods missing). Assign `window.Game_MyThing = Game_MyThing;` or store plain data.
9. **Storing progress in `$data*`.** Database objects are not saved; mutate `Game_*` objects or `$gameSystem` fields instead.
10. **1.9.0 / 1.10.0 icon and face sizes.** 1.9.0 made `ImageManager.iconWidth/iconHeight/faceWidth/faceHeight` editor-configurable and added `ImageManager.standardIconWidth`, `standardIconHeight`, `standardFaceWidth`, `standardFaceHeight` (used by Window_Base drawing). 1.10.0 renamed `defaultIconWidth`/`defaultFaceWidth` to the `standard*` names. Plugins hard-coding 32/144 or using the `default*` names may misdraw; use the `standard*` properties for layout.
11. **1.8.0 boot change.** `Scene_Boot.startNormalGame` now goes to `Scene_Splash`, not `Scene_Title`; title-skip plugins that alias the old path need updating.
12. **Load order.** Plugins are evaluated top to bottom; an alias of a method another plugin replaces later is lost. Declare `@base`/`@orderAfter`.
13. **Using Node APIs on web.** `require("fs")` only exists in NW.js (desktop/playtest); `StorageManager.isLocalMode()` is false in browsers, where saves go to IndexedDB via localforage.

## Rendering
PixiJS 5.3 (WebGL) wrapped by core classes: `Graphics`, `Bitmap` (canvas-backed, `drawText`, `fillRect`, `blt`), `Sprite`, `Tilemap` (autotiles), `Window` (windowskin), `WindowLayer`, `Spriteset_Map`/`Spriteset_Battle`. Default resolution 816x624 (configurable in System 2; 1.10.0 adds a 1280x720 template). Animations use Effekseer (`effects/*.efkefc`), with an official plugin for MV-style sprite animations.

## Physics
No physics engine. Movement is grid/tile based (`Game_CharacterBase` with passability from tilesets and region/terrain tags); collisions are tile passability and event priority/trigger types (Action Button, Player Touch, Event Touch, Autorun, Parallel). Pixel movement or physics needs third-party plugins.

## Input
`Input` (keyboard + gamepad mapped to symbols: `"ok"`, `"cancel"`, `"shift"`, `"menu"`, `"pageup"`, `"pagedown"`, `"up"`, `"down"`, `"left"`, `"right"`, `"escape"`, `"tab"`, `"control"`, `"debug"`). Methods: `Input.isPressed`, `isTriggered`, `isRepeated`, `isLongPressed`, `Input.dir4`, `Input.dir8`. Extend keys by adding to `Input.keyMapper[keyCode] = "symbol"`. `TouchInput.isTriggered()`, `TouchInput.x/y`, `isCancelled()` (right-click/two-finger).

## UI
Window classes: `Window_Base` (drawText, drawIcon, drawFace, drawTextEx with escape codes `\C[n]`, `\I[n]`, `\V[n]`), `Window_Selectable`, `Window_Command` (`makeCommandList`, `addCommand(name, symbol, enabled)`, `setHandler(symbol, method)`), `Window_HorzCommand`, `Window_Help`, `Window_Gold`, `Window_Message`. Scenes extend `Scene_MenuBase` for menu screens. Pictures (`Show Picture`) and the official TextPicture / ButtonPicture plugins provide event-driven UI. MZ also has on-screen touch buttons (`Sprite_Button`) toggled by `ConfigManager.touchUI`.

## Networking and multiplayer
No built-in support. Plugins can call `fetch`/WebSocket (browser APIs) for leaderboards or analytics; online multiplayer requires custom server work and is uncommon.

## Save data
- Event command *Save* / save screen calls `DataManager.saveGame(savefileId)`: `makeSaveContents()` (system, screen, timer, switches, variables, selfSwitches, actors, party, map, player) -> `JsonEx.stringify` -> pako zip -> `StorageManager.saveObject`. Global info (slot list) in `global`.
- Desktop/NW.js: files in `save/` (`fileN.rmmzsave`, `global.rmmzsave`, `config.rmmzsave`); browser: IndexedDB through localforage.
- To add data: put fields on an existing saved object (e.g. `$gameSystem._myPluginData = {...}` initialised in an aliased `Game_System.prototype.initialize`) or alias `DataManager.makeSaveContents`/`extractSaveContents`. Old saves will lack the field: default it on load.
- `$gameTemp`, `$gameMessage`, `$gameTroop` are **not** saved (explicit comment in core).
- ConfigManager (options) is saved separately in `config`.

## Performance
Keep parallel events few (each runs every frame), avoid `Wait 0` busy loops in parallel processes, prefer region IDs to many events, refresh windows only on change (not every frame `refresh()`), cache Bitmaps, limit huge parallax images on mobile, and use "Exclude unused files" on deploy (with `@requiredAssets` for plugin-loaded images). Profile with NW.js DevTools (F8 in playtest).

## Build and export
File > Deployment: Windows (game folder with Game.exe on NW.js), macOS (Game.app), Web browsers (upload folder to a server; requires WebGL; iOS 12+ / Android 8+ browsers). Options: *Exclude Unused Files* (may remove plugin-only assets unless declared), image and audio *Encryption* with a key (not real protection). Mobile apps: wrap the web output (Cordova/Capacitor/WebView) yourself. Playtest: Ctrl+R / toolbar; F8/F12 open DevTools; F9 debug menu.

## Common bugs and fixes
| Symptom | Cause | Fix |
|---|---|---|
| Plugin command appears but does nothing | `pluginName` string differs from file name, or command name typo vs `@command` | Make them identical (case-sensitive key `file:command`) |
| Plugin command not listed in editor | Missing `@target MZ`, annotation outside `/*: */`, or plugin disabled | Fix header; re-open Plugin Manager, click Refresh |
| `"false"` parameter behaves as true | Parameters are strings | `params.flag === "true"` |
| `TypeError: x is not a function` after loading a save | Custom class not on `window`, JsonEx restored a plain object | `window.MyClass = MyClass` or save plain data |
| `Window_Base` draws at 0,0 with zero size | MV-style `(x, y, w, h)` args in MZ | Pass `new Rectangle(x, y, w, h)` |
| Other plugin's feature broke after adding yours | Overwrote a method without calling the alias | Alias pattern with `.apply(this, arguments)`; check order |
| Images missing in deployed game | Exclude Unused Files removed plugin-loaded images | `@requiredAssets` or `@dir`/`@type file` params |
| `require is not defined` in browser build | NW.js-only API | Guard with `Utils.isNwjs()` / use StorageManager |
| Icons misaligned after 1.9/1.10 update | Hard-coded 32px or old `default*` names | Use `ImageManager.standardIconWidth` / `standardIconHeight` |
| Save from older version throws on new field | Field added by plugin later | Default missing fields on load (`extractSaveContents` alias) |

## Minimal example
A plugin that adds a gold HUD window on the map and a "Coin" plugin command that awards gold and plays a sound. Movement and collisions come from the engine (player walks with arrows; a map event with trigger *Player Touch* calls the command).
```js
/*:
 * @target MZ
 * @plugindesc Gold HUD on the map plus a Collect Coin command.
 * @author STAR example
 * @help Place an event with trigger "Player Touch" that runs
 * Plugin Command > CoinHud > Collect Coin, then Erase Event.
 *
 * @command collect
 * @text Collect Coin
 * @desc Adds gold and refreshes the HUD.
 *
 * @arg value
 * @text Value
 * @type number
 * @min 1
 * @default 10
 */
(() => {
  "use strict";
  const pluginName = "CoinHud"; // file: js/plugins/CoinHud.js

  class Window_CoinHud extends Window_Base {
    initialize(rect) {
      super.initialize(rect);
      this._lastGold = -1;
      this.refresh();
    }
    update() {
      super.update();
      if (this._lastGold !== $gameParty.gold()) this.refresh();
    }
    refresh() {
      this._lastGold = $gameParty.gold();
      this.contents.clear();
      this.drawText(`Coins: ${this._lastGold}`, 0, 0, this.innerWidth, "left");
    }
  }
  window.Window_CoinHud = Window_CoinHud;

  const _Scene_Map_createAllWindows = Scene_Map.prototype.createAllWindows;
  Scene_Map.prototype.createAllWindows = function() {
    _Scene_Map_createAllWindows.apply(this, arguments);
    const rect = new Rectangle(0, 0, 240, this.calcWindowHeight(1, false));
    this._coinHudWindow = new Window_CoinHud(rect);
    this.addWindow(this._coinHudWindow);
  };

  PluginManager.registerCommand(pluginName, "collect", function(args) {
    $gameParty.gainGold(Number(args.value));
    AudioManager.playSe({ name: "Coin", volume: 90, pitch: 100, pan: 0 });
  });
})();
```
(`calcWindowHeight(numLines, selectable)` is a Scene_Base helper in MZ; "Coin" must exist in `audio/se`.)

## RPG Maker Unite (brief)
Unity-based RPG Maker sold on the Unity Asset Store (released 2023). Customisation is C# addons managed by an Addon Manager or direct source edits in the Unity Editor; MZ JavaScript plugins do **not** run in Unite. Current official notice: version 1.3.1 (2 Sep 2026). Treat Unite questions as Unity/C# plus Unite's own addon API (not researched in depth here).
