# Design: test STAR-generated Luau without Roblox Studio

**Status:** design only, 2026-10-12. **Decision:** extend the already-merged, checksum-pinned official Luau CLI spec runner with an opt-in, deliberately incomplete Roblox test-double layer. No code, feature flag, installer change, or runtime capability is introduced by this document.

## Question and acceptance criteria

Can STAR execute generated Luau, catch real assertion/runtime failures, and report a *truthful* result on Windows and Linux, without Studio, paid services, Roblox credentials, network access during test execution, or pretending that a mocked engine is Roblox?

Judge alternatives on: (1) actual Luau execution rather than only parsing; (2) ability to test useful Roblox-facing logic; (3) false-positive risk; (4) deterministic, offline, bounded and safe execution of generated code; (5) Windows support, pinned supply chain, download footprint and licence; (6) maintenance/reuse of STAR's current code; and (7) demonstrable failure-before/fix-after coverage. **Do not count a mock pass as Roblox Studio or live-game verification.**

## Contract of a trustworthy headless result

Proposed verdicts (new, not existing STAR API): **`NATIVE_LUAU_PASS`** for actual unmodified logic under standalone Luau; **`SIMULATED_PASS`** for a declared fake Roblox capability with passing assertions; **`FAILED`** for assertion/runtime/suite failure; **`UNSUPPORTED`** when engine services/functions/fixtures are missing; **`NOT_RUN`** for an absent binary or disabled opt-in. A pass against doubles **must never be presented as a Roblox Studio pass**. Preserve per-spec assertion names, exit codes, source locations and a machine-readable declared capability set.

- Keep current official CLI spec path as the default; enable expanded fakes only by an explicit owner opt-in. Unknown class/property/member/service, accidental nil lookup, missing spec, zero cases and unsupported API must **fail loudly**, not silently return inert tables or be skipped. Avoid broad regex rewriting of arbitrary generated scripts; require an explicit module layout and supported fixture set. Sources for *current* behavior: [runner](../../scripts/run_luau_specs.py), [runner tests](../../tests/test_run_luau_specs.py).
- Run generated code only from copied temporary sources; never mount local secrets. Retain subprocess timeouts, output byte limits, finite test budgets and isolation; add an OS-enforced resource limit when shipping user-generated execution. The official CLI README says its REPL is sandboxed except for module `require`; this is **not** a substitute for a host OS security boundary. Lune's own security guide says untrusted scripts have host access. [Luau README](https://github.com/luau-lang/luau/blob/master/README.md), [Lune security](https://lune-org.github.io/docs/getting-started/4-security/), [current runner](../../scripts/run_luau_specs.py).
- Use a deterministic fake clock, explicit event injection and fresh reset per spec; no sleeping to make timing assertions pass. Do not automatically simulate a `Touched` when CFrame changes: Roblox documents that it fires from physical movement, not mere property overlap. [task](https://create.roblox.com/docs/reference/engine/libraries/task), [BasePart](https://create.roblox.com/docs/reference/engine/classes/BasePart).
- Each supported behavior needs a positive assertion and a **negative control** (wrong ordering, missing service, timeout, disconnected signal, rejected datastore write, etc.). Where the true engine ordering is not known from docs or recorded native observation, label the behavior an *assumed double contract*, not parity. Do not mark an auto-generated fixture a trusted oracle without review. Sources of expected engine API: the Creator Documentation referenced below.

## First 20 Roblox behaviors for the double layer

**All twenty are requirements, not claims of current support.** Expose an explicit fixture API to inject clock advances, part-contact pairs, player joins/leaves, datastore failures and client/server remote calls. Use the official method/event spellings; an unsupported operation throws a tagged error. The source column is the external reference for the engine behavior, while the middle column describes a proposed deterministic **approximation**.

| # | Required behavior / test oracle | Official contract |
| --- | --- | --- |
| 1 | `game:GetService(name)` returns the same known service object for repeated calls; unknown services fail. | [DataModel](https://create.roblox.com/docs/reference/engine/classes/DataModel) |
| 2 | `Instance.new(className)` creates supported class defaults with `Parent == nil`; invalid/unsupported names fail. | [Instance](https://create.roblox.com/docs/reference/engine/classes/Instance) |
| 3 | Assigning `Parent` updates old/new ancestry and prevents invalid destroyed-object parenting. | [Instance](https://create.roblox.com/docs/reference/engine/classes/Instance) |
| 4 | `GetChildren()` and `GetDescendants()` enumerate the *current* tree; a reparented child appears once. | [Instance](https://create.roblox.com/docs/reference/engine/classes/Instance) |
| 5 | `FindFirstChild(name)` finds immediate children; `WaitForChild(name, timeout)` yields until insertion or returns nil on timeout. | [Instance](https://create.roblox.com/docs/reference/engine/classes/Instance) |
| 6 | `IsA(className)` respects inheritance (`Part` is a `BasePart` and `Instance`), not just exact class names. | [Instance](https://create.roblox.com/docs/reference/engine/classes/Instance) |
| 7 | `Clone()` copies eligible descendants respecting `Archivable` and yields a parentless clone. | [Instance](https://create.roblox.com/docs/reference/engine/classes/Instance) |
| 8 | `Destroy()` recursively detaches, locks parenting and disconnects associated signals. | [Instance](https://create.roblox.com/docs/reference/engine/classes/Instance) |
| 9 | `ChildAdded` / `ChildRemoved` fire for explicit reparent operations with the correct object. | [Instance](https://create.roblox.com/docs/reference/engine/classes/Instance) |
| 10 | `RBXScriptSignal:Connect()`, `:Once()` and `RBXScriptConnection:Disconnect()` enforce exactly-once/unsubscribe behavior. | [Events](https://create.roblox.com/docs/scripting/events) |
| 11 | `RBXScriptSignal:Wait()` resumes a waiting coroutine with event parameters; destroyed sources release/disconnect handlers safely. | [Events](https://create.roblox.com/docs/scripting/events) |
| 12 | `BasePart.Touched` delivers an *explicitly injected* other part; fixture checks `CanTouch` and does **not** fake collision detection. | [BasePart](https://create.roblox.com/docs/reference/engine/classes/BasePart) |
| 13 | `Players:GetPlayers()` returns only joined players; `GetPlayerByUserId()` resolves the injected user. | [Players](https://create.roblox.com/docs/reference/engine/classes/Players) |
| 14 | Injected joins/removals fire `Players.PlayerAdded` / `PlayerRemoving`, with removal before membership is cleared. | [Players](https://create.roblox.com/docs/reference/engine/classes/Players) |
| 15 | Injected `Player.CharacterAdded` / `CharacterRemoving` and character-to-player lookup model respawn in a fixed sequence. | [Player](https://create.roblox.com/docs/reference/engine/classes/Player), [Players](https://create.roblox.com/docs/reference/engine/classes/Players) |
| 16 | `task.spawn` schedules promptly and `task.defer` runs at the next resumption point; tests assert phase boundaries. | [task](https://create.roblox.com/docs/reference/engine/libraries/task) |
| 17 | `task.delay`, `task.wait` and `task.cancel` work under a controllable fake clock, with no wall-time sleeps. | [task](https://create.roblox.com/docs/reference/engine/libraries/task) |
| 18 | `TweenService:Create()` and `Tween:Play()/Pause()/Cancel()` transition state and `Completed` reports completion vs cancellation for *supported numeric properties*. | [TweenService](https://create.roblox.com/docs/reference/engine/classes/TweenService), [TweenBase](https://create.roblox.com/docs/reference/engine/classes/TweenBase) |
| 19 | `DataStoreService:GetDataStore(name, scope)` returns shared in-memory scope; fake `GetAsync/SetAsync/UpdateAsync/RemoveAsync` honor write/read assertions and injected errors. Never use real data. | [DataStoreService](https://create.roblox.com/docs/reference/engine/classes/DataStoreService), [GlobalDataStore](https://create.roblox.com/docs/reference/engine/classes/GlobalDataStore) |
| 20 | A fake `RemoteEvent:FireServer()` supplies the authoritative injected `Player` to `OnServerEvent`; `FireClient/FireAllClients` target the intended fake recipients only. This tests handler routing, **not** actual replication or exploit resistance. | [RemoteEvent](https://create.roblox.com/docs/reference/engine/classes/RemoteEvent) |

**Deliberately not in first scope:** actual rigid-body motion/contact generation, full engine frame scheduling, network loss/latency, remote serialization/rate limits, DataStore throttling and persistence, client streaming, physics constraints, UI rendering, multiplayer server topology and animation. These need separate Studio/live-engine evidence. Sources: [BasePart](https://create.roblox.com/docs/reference/engine/classes/BasePart), [RemoteEvent](https://create.roblox.com/docs/reference/engine/classes/RemoteEvent), [DataStoreService](https://create.roblox.com/docs/reference/engine/classes/DataStoreService), [RunService](https://create.roblox.com/docs/reference/engine/classes/RunService).

## Recommendation and phased implementation: at most five small PRs

**Choose A + C**: retain Luau CLI as the real language execution engine and grow *narrow, observable test doubles* behind an explicit opt-in, reusing the existing runner and 13 passing spec files. Lune is an optional future replacement for file/model tooling, not a drop-in engine simulator or a safe untrusted-code sandbox by itself. Existing code and security boundaries: [runner](../../scripts/run_luau_specs.py), [CI](../../.github/workflows/luau-specs.yml), [Lune API status](https://lune-org.github.io/docs/roblox/4-api-status/), [Lune security](https://lune-org.github.io/docs/getting-started/4-security/).

1. **PR 1 — smallest next step: expose and fix one semantic false negative.** Add a narrow `Part:IsA("BasePart")` / `Part:IsA("Instance")` spec under `examples/roblox-templates/rounds/ServerScriptService/Tests/`; extend the existing `ENGINE` inheritance handling in `scripts/run_luau_specs.py`; add a native-CLI regression in `tests/test_run_luau_specs.py`. Assert that the *unfixed* stub fails this spec while the corrected stub and existing 13 pass. Do **not** add a general app feature or hook into answer generation.
2. **PR 2 — explicit opt-in core doubles.** Extract only the present `ENGINE` stand-in into test-owned modules under proposed `scripts/luau_headless/`, add service registry, instance tree, lifecycle and signal contracts (#1–11), and add `--headless`/fixture selection to `scripts/run_luau_specs.py` with the default pure runner unchanged. Verify both unsupported-property rejection and old spec parity via `tests/test_run_luau_specs.py`.
3. **PR 3 — inject rather than invent the world.** Add fake `Players`/characters, manual `Touched` injection and server/client `RemoteEvent` fixtures (#12–15, #20) inside `scripts/luau_headless/`, with negative controls for disconnected handlers and wrong sender, plus real Luau spec fixtures. Leave physics and real replication unsupported.
4. **PR 4 — deterministic clock and tween lifecycle.** Implement #16–18 using an injectable clock and a small numeric tween model. Run assertions without sleeps, including cancellation and incorrect-order negative controls. Keep whole-engine frame timing explicitly unverified.
5. **PR 5 — in-memory DataStore semantics and evidence reporting.** Implement #19 with shared name/scope maps, explicit errors, cancellable updates and fresh reset per test; add capability-tagged summary separating native, simulated and unsupported outcomes. Add Windows pinned-CLI CI smoke coverage only if the Windows sandbox/packaging contract is established; otherwise track it as a separate follow-up (not a false green). App integration remains **off** until the owner opts in.

**Pass gate for each future PR:** an assertion that demonstrably fails under the previous implementation, then passes under the changed implementation when the **actual Luau binary** executes the spec; existing **13/13** continue passing; pytest runner-path cases cover subprocess failure/timeout/unsupported; no network or secrets needed to run tests. GitHub CI and real-Windows execution must be reported separately, with numbers. A passing mocked test does not replace the native Studio acceptance tests described in [docs/STUDIO_BUILD_REPAIR.md](../STUDIO_BUILD_REPAIR.md).

### What would change the decision?

Re-evaluate Lune only if its documented API coverage plus an *actually enforced* untrusted-script isolation boundary make equivalent fixtures smaller and safer, and a fixed native-Luau practice set measures no loss of defect detection (including negative controls) on Windows and Linux. Upgrading pinned Luau or adopting new tooling likewise requires version/checksum review and a real CI before/after result. **Unmeasured hypotheses:** relative runtime speed, installed memory footprint, cross-platform timing parity, and how many generated Roblox scripts need each mocked service.

### Open decisions (not blockers for this design)

- Who owns the exact capability/unsupported list and verifies semantic parity against small native Studio fixtures? Some engine ordering and failure edge cases are not fully specified by public docs.
- Should Windows ARM64 be supported initially or only the published x86_64 artifact? Existing `luau-specs` is Linux-only.
- How much DataStore retry, session-lock and request-budget fidelity is worth maintaining? A fake datastore cannot prove remote persistence.
- What explicit licence governs STAR-created test-double code if redistributed? The inspected repository root has no top-level `LICENSE` file.

**Concrete recommendation:** keep `scripts/run_luau_specs.py` and the pinned Luau 0.691 CLI as STAR's executable truth source, and use explicitly named simulated evidence only when the owner enables it. **Smallest next PR:** add the `IsA` inheritance failing spec and fix to the current `ENGINE` shim, verified by native Luau plus `tests/test_run_luau_specs.py`—no new runner, Studio dependency, or app behavior.
