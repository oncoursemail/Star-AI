# STAR local multi-model router — Windows review guide

**Candidate only:** stacked on STAR Ultimate Brain PR #34. This is **not** part of STAR's stable release, and no Qwen3.8-27B benchmark has been run on the owner's computer.

## What is implemented

The React desktop Settings -> STAR model team now has a real **Start model router** action. It starts the already-installed, fixed `llama-server.exe` on `127.0.0.1:8080`, reading GGUF files only from the user-selected model directory (including one direct subfolder per model).

The server starts with:
- `--models-dir <selected absolute local folder>`
- `--models-max 1` (only **one model resident** at a time; no accidental simultaneous 27B + 9B RAM exhaustion)
- `--ctx-size 4096` by default, adjustable 512–32768; `-np 1`
- user-configurable `-ngl 25` default, 0–1000 in Settings
- `--host 127.0.0.1`, no shell, no public listen, `--jinja`

This preserves the current pinned Qwen3.5-4B single-model startup path. Starting a router requires explicit user action; if an existing managed model is running, **Stop managed Brain** first. Stopping affects the running process only. `%APPDATA%/STAR` chats, caches, downloads, memory, presets and model files are never deleted or migrated.

The router is a way to **choose and load one specialized model at a time**, not to combine their weight matrices or make them simultaneously active. The model selection fields in Settings route different *requests* to listed IDs. With 32 GB system RAM / 8 GB VRAM, switching a 4B and 27B model may require evicting/reloading the previous one and can take far longer than a small-model response.

## First-time setup

1. Install STAR's verified existing Windows preview and bundled llama.cpp runtime according to the Fast Brain PR; use a disposable test/backup before trying this candidate.
2. Obtain GGUF model files from their official publisher or a clearly licensed, trustworthy conversion. **STAR does not auto-download 27B weights**, and this PR makes no claim about artifact license or file hashes until independently checked.
3. Put a small model directly in your selected folder (example `C:\\Models\\STAR\\qwen-4b.gguf`). Place multi-shard or multimodal models in a named subfolder, alongside their `mmproj-*.gguf` file if needed. Do not place partial `.gguf` downloads or symlinks in the folder.
4. STAR Desktop -> **Settings -> STAR model team -> Managed GGUF models**. Select the directory through **Choose folder**. Keep context at 4096 initially and choose conservative GPU layers. Save/start with **Start model router**.
5. Wait for STAR to report that the router's `/models` endpoint is reachable. This is **not** proof that 27B loaded successfully or supports vision/tools.
6. Click **List available models** and set Primary, Fast, Reasoning, Roblox and Vision model IDs to exactly those returned by your router. Leave optional specialist slots empty to use the primary.
7. Save, then **Test model team**. It sends a fixed tiny *text-only* probe to each distinct model ID. With a huge model, this may be slow while weights load/offload. Read model-specific errors rather than silently switching providers.
8. Run STAR chat Fast/Auto/Agent tasks. Use the local benchmark below; inspect Studio screenshots and functionality before judging Roblox quality.
9. Use **Stop managed Brain** to stop the owned llama.cpp process, not other independent servers.

If the installed `llama-server.exe` predates router support, or the model folder uses an incompatible GGUF conversion, the router will fail with a visible error and an on-device log under `STAR/logs/star-router-react.log`. Do not attempt to fix compatibility by granting an AI arbitrary shell access or replacing binaries without signature/hash review.

## Sensible hardware policy

A 27B Q4 GGUF may need roughly 16.5 GB just for weights, plus context cache, projection and Windows/Roblox/Blender memory. A 32 GB DDR4 PC with 8 GB VRAM cannot hold its weights entirely on GPU. Do not promise a 27B will be faster than Qwen3.5-4B. Test 4B, 9B and 27B with identical prompts before assigning model roles. When VRAM is insufficient, reduce `-ngl` and context, and check whether CPU offload is unacceptably slow.

Example on-device measurement (replace MODEL-ID with the actual server ID):

    py -3.11 -m star.brain_benchmark --model MODEL-ID --scenario chat --runs 5
    py -3.11 -m star.brain_benchmark --model MODEL-ID --scenario roblox --runs 5

The benchmark reports wall time, first visible token and observed throughput, not fabricated gains.

## Security and limitations

- Model directory inspection is bounded and rejects symlink paths, tiny/incomplete GGUFs and over-large folder catalogs. Folder selection is owner-driven; never generated by model text.
- No arbitrary off-device fallback. Cloud providers are a separate explicit Settings selection with their existing OS keyring credentials.
- Explicit Test team performs a real text completion, but **does not verify** tool calling, image input, R6/R15 compatibility, Studio edits, Python/Luau semantics, performance, or the accuracy of any answer.
- Router may enumerate llama.cpp's own model cache in addition to the selected models directory; only use a trusted local llama.cpp installation and review server-listed IDs before choosing a model.
- Running an AI model **does not retrain** it. STAR's separate rights-confirmed SFT dataset preparation does not update GGUF weights.

Official source for router flags, model folders, model autoload and `/models`: https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md

Other project docs: [STAR Ultimate Brain v1](STAR_ULTIMATE_BRAIN_V1.md), [Fast Brain Windows review](STAR_FAST_BRAIN_WINDOWS_REVIEW.md).

## Instant answers while STAR Server is selected

When STAR Server (LAN) is the selected chat provider, short standalone text questions in
Fast or Auto mode can use an already-installed **and already-loaded** on-device model.
The pure eligibility check excludes Agent mode, attachments, tools, Roblox/Luau and
other coding, documentation lookup, research, deep requests, and complex follow-ups.
The normal STAR Server route remains unchanged for all excluded requests.

STAR sends a short GET to the configured loopback `/v1/models` endpoint and only
considers a model explicitly marked loaded (or the sole model on a single-model
endpoint without status). It does **not** start, install, download, swap, or preload
models. For qualifying questions, the local reply is buffered rather than streamed
to the UI. If it fails, produces no first visible text within 1.75 seconds, or
cannot finish within 12 seconds, the buffered text is discarded and the ordinary
STAR Server answer is tried once. Only one completed assistant message is stored.

**Settings → Advanced settings → Interface & performance → Instant answers on
this PC** is explicitly OFF by default. Enabling it allows instant answers only
when a local model is configured and already loaded. The activity line reports which
brain answered and first-token/throughput observations; token rates without
provider-reported usage are marked approximate. The existing endpoint validation
keeps requests on loopback or the selected, validated private LAN server. Hardware
speed and quality must still be measured on the owner's PC; no specific latency
claim is made by these tests.

## Required verification before production

- Python pytest and compileall, React TypeScript/Vitest/Vite, Windows packaged Qt WebChannel and Inno Setup smoke tests.
- Real Windows hardware with a router-capable `llama-server.exe`; 4B and 27B success/failure; orphan processes and Stop behavior.
- Test changing models under normal memory load, log only nonsecrets and verify data survives program upgrades.
- Roblox Studio MCP script edits, screenshot comparisons, animation clips and performance measurements on a disposable unpublished place.
- Human review and integration with active UI/MCP/agent forks before merging main. Public release only through separately approved workflow.
